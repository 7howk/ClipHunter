# Backend и инфраструктура: этапы

## Этап 1 — выполнен

Запускаемая основа FastAPI, health, Swagger, разделение слоёв, PostgreSQL и MinIO
в Compose, правила репозитория, документация и CI.

## Этап 2 — выполнен

Реализованы четыре доменные сущности, ORM-модели SQLAlchemy 2.0, PostgreSQL через
asyncpg, начальная миграция Alembic, интерфейсы репозитория и транзакции,
сценарии создания/получения/списка проектов, HTTP API и единый формат ошибок.
Тестируются сущности, сценарии, API, реальный репозиторий и ограничения базы.

## Этап 3 — выполнен

Реализованы потоковая загрузка двоичного тела запроса, проверка имени, расширения,
MIME, настоящего видеопотока, размера, длительности и свободного диска.
`ffprobe` используется только для метаданных. Видео сохраняется в S3-совместимом
MinIO/R2, проект переходит в `uploaded`. Локальный бакет готовится в Compose.
Есть защита от повторной и конкурентной загрузки, очистка временных файлов
и обработка ошибок хранилища. Проверки включают настоящий MP4 и multipart MinIO.

## Этапы 4 и 5 — выполнены

Отдельный worker берёт задачи из очереди PostgreSQL, скачивает оригиналы,
извлекает аудио и делит его на части. Groq Whisper расшифровывает звук,
GPT-OSS выбирает моменты по тексту реплик. Таймкоды определяются по расшифровке.
Реализованы запуск обработки, опрос статуса и API хайлайтов.

## Этап 6 — выполнен

Worker генерирует MP4 для выбранных хайлайтов. API возвращает статус клипа и
подписанную ссылку на скачивание. Повторный запуск переиспользует активный клип.
Удаление проекта ставит его файлы в очередь очистки S3.
