# Backend ClipHunter

Текущий этап предоставляет устанавливаемое приложение FastAPI, настройки
окружения, метод проверки работоспособности, API проектов и документацию API. Проекты
сохраняются в PostgreSQL через SQLAlchemy 2.0; схема управляется Alembic.
Загрузка файлов, объектное хранилище, обработка видео и ИИ появятся позже.

## Архитектура

Пакет `src/cliphunter` разделён на четыре слоя:

| Пакет | Назначение |
| --- | --- |
| `domain` | Бизнес-сущности и интерфейсы репозиториев; только стандартная библиотека |
| `application` | Сценарии использования, DTO и интерфейсы сервисов; зависимости направлены внутрь |
| `infrastructure` | Настройки окружения; в дальнейшем — адаптеры базы, хранилища и внешних сервисов |
| `presentation/http` | HTTP-маршруты и схемы ответов Pydantic |

`main.py` связывает компоненты через фабрику `create_app()`. Domain содержит VideoProject, TranscriptSegment, Highlight и GeneratedClip.
Application реализует создание, получение и список проектов через интерфейсы
репозитория и транзакции; доступ к SQLAlchemy остаётся в infrastructure. Метод проверки состояния
не содержит бизнес-логики и не требует отдельного сценария или репозитория.

Для запуска используются Python 3.12–3.14, FastAPI, Pydantic v2/settings, Uvicorn, SQLAlchemy 2.0, asyncpg и Alembic.
Для тестирования и проверок — Pytest, HTTPX2 (Starlette TestClient), Ruff и MyPy.
Версии прямых и транзитивных зависимостей приложения закреплены в
`requirements.lock`; инструменты разработки в Docker-образ не устанавливаются.

## Запуск без Docker

Выполните из корня репозитория, используя Python 3.12+:

```sh
python3 -m venv backend/.venv
. backend/.venv/bin/activate
python -m pip install -c backend/requirements.lock -e './backend[dev]'
cp .env.example .env
python -m cliphunter
```

Если `.env` уже настроен, сохраните его вместо повторного копирования примера.
Приложение читает `.env` из текущего рабочего каталога; переменные окружения
процесса имеют приоритет. Для чтения общего `.env` запускайте API из корня
репозитория. Сейчас используются следующие настройки:

| Переменная | По умолчанию | Проверка |
| --- | --- | --- |
| `APP_ENV` | `development` | `development`, `test` или `production` |
| `APP_HOST` | `0.0.0.0` | Непустой адрес для запуска сервера |
| `APP_PORT` | `8000` | Целое число от 1 до 65535 |
| `DATABASE_URL` | Не задано | URL PostgreSQL с драйвером `postgresql+asyncpg` |

Для API проектов требуется `DATABASE_URL`. Без него health и Swagger доступны,
а API проектов возвращает 503. Для запуска на компьютере замените в URL имя
`postgres` на `localhost`. Остальные значения настраивают Compose или будущие
интеграции с хранилищем и ИИ. Полные настройки и переменные окружения нельзя записывать в логи.
Развёртывание в production будет подготовлено отдельно.

Для автоматического перезапуска при изменениях выполните из корня репозитория
в активированном окружении:

```sh
python -m uvicorn cliphunter.main:create_app --factory --reload --host 127.0.0.1 --port 8000
```

## Контракт API

`GET /api/v1/health` возвращает HTTP 200 с типом `application/json`:

```json
{"status": "ok"}
```

Метод проверяет работу процесса API. Готовность базы и хранилища проверяется
отдельно. Авторизация и обработка видео ещё не реализованы.

- Swagger UI: http://localhost:8000/docs.
- OpenAPI: http://localhost:8000/openapi.json.

Доступные методы:

| Метод | Адрес | Результат |
| --- | --- | --- |
| POST | `/api/v1/projects` | Создать проект из JSON `{"title":"Мой стрим"}`, ответ 201 |
| GET | `/api/v1/projects?limit=20&offset=0` | Список: `items`, `total`, `limit`, `offset` |
| GET | `/api/v1/projects/{id}` | Данные проекта |
| GET | `/api/v1/projects/{id}/status` | Статус и время его обновления |

Новый проект имеет статус `created`; поля видео пока равны `null`. Внутренний
ключ хранилища не входит в ответ. Для списка допустимы `1 <= limit <= 100`
и `offset >= 0`; порядок — от новых проектов к старым.

Ошибки имеют вид `{"error":{"code":"not_found","message":"Проект не найден"}}`.
Используются 404 для отсутствующих проектов, 422 для неверных параметров
и 503 при недоступной базе. В ответах нет SQL, паролей и исходных данных ошибок.

## Проверки

Активируйте окружение разработки и выполните из каталога `backend/`:

```sh
ruff check .
ruff format --check .
mypy src
pytest
```

Модульные тесты проверяют сущности, сценарии, HTTP-контракт и настройки без
внешних сервисов. Интеграционные тесты репозитория и ограничений требуют отдельной
базы PostgreSQL с применёнными миграциями. Задайте её URL в `TEST_DATABASE_URL`;
без него эти тесты пропускаются. Настоящие внешние API-ключи не нужны. GitHub Actions
запускает проверки на Python 3.12 и 3.13, а также отдельно собирает и проверяет
полный стек Docker Compose.

## Миграции базы данных

Из корня репозитория с активированным окружением и настроенным `DATABASE_URL`:

```sh
alembic -c backend/alembic.ini upgrade head
alembic -c backend/alembic.ini check
```

Compose выполняет миграции отдельным одноразовым сервисом `migrate` до запуска
API. Автоматического `create_all` в приложении нет. Начальная миграция создаёт
проекты, сегменты транскрипции, хайлайты и клипы с ограничениями, индексами
и каскадным удалением. Создавайте новые миграции через `revision --autogenerate`,
проверяйте полученный код и не изменяйте уже применённые ревизии.

Запуск в контейнерах описан в [документации инфраструктуры](../infra/README.md).
